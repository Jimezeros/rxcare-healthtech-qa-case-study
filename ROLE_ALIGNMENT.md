# Portfolio-to-Role Alignment

This document maps the RxCare artifacts to the capabilities demonstrated by the portfolio without overstating technical seniority or employment history.

| Target direction | Portfolio evidence |
|---|---|
| Junior Manual QA / QA Analyst | Testable story, Gherkin acceptance criteria, structured UI test designs, executed API-contract cases, an honestly blocked live-browser run, evidence-backed candidate-risk decision, and traceability |
| Junior QA / Technical QA direction | Local browser workspace, Python validation, automated unit/integration tests, HTTP-handler and UI-contract tests, JUnit output, and reproducible evidence capture |
| HealthTech Data Quality | Synthetic e-prescription rule, SQLite constraint, missing-data SQL checks, duplicate protection, privacy-safe audit events, and safety-oriented risk analysis |
| Product / Business Analysis | Product boundary, measurable acceptance criteria, requirement-to-test mapping, and explicit implemented-versus-planned scope |
| Data / Operations direction | Parameterised SQL, canonical-versus-audit data separation, UTC/version metadata, and deterministic quality-check outputs |

## Professional boundaries

- This repository demonstrates structured portfolio practice, not prior employment as a professional QA engineer.
- Jira capability is demonstrated through hands-on portfolio application.
- Only the API/service/database cases actually run against v0.2.0 are marked Passed.
- The local UI is implemented and contract-tested, but the UI-oriented Jira cases remain `Blocked — Not Executed` because this environment denied the required loopback listener.
- RXQA-10 remains a candidate risk because it was not reproduced through the API path; no UI reproduction result is claimed.
- No confidential healthcare, employer, client, or production data is used.
- Authentication/RBAC, AI evaluation, deployment, clinical validation, and regulatory compliance are not claimed.
- A static UI preview demonstrates layout only; it is not manual-test evidence.
